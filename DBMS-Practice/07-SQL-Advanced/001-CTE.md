# CTE (Common Table Expressions)

## Scenario
A report query has become an unreadable wall of nested subqueries computing "active customers," then "their order totals," then "top 10 by spend." You need to make it maintainable.

## Solution
```sql
WITH active_customers AS (
    SELECT id, name FROM customers WHERE is_active = TRUE
),
customer_totals AS (
    SELECT ac.id, ac.name, SUM(o.total) AS total_spent
    FROM active_customers ac
    JOIN orders o ON o.customer_id = ac.id
    GROUP BY ac.id, ac.name
)
SELECT *
FROM customer_totals
ORDER BY total_spent DESC
LIMIT 10;
```

A CTE (`WITH ... AS (...)`) names an intermediate result set so later parts of the query can reference it like a table - turning a deeply nested subquery into a readable, top-to-bottom sequence of named steps.

## Takeaway
CTEs don't (in most modern engines) change what's computable - anything a CTE does, a subquery could too - but they dramatically improve readability and make queries easier to debug step by step by giving intermediate results a name.
