# 2NF (Second Normal Form)

## Scenario
Your `order_items` table has a composite primary key `(order_id, product_id)`, but also stores `product_name`, which only depends on `product_id`, not on the full key.

## Diagram
```
order_items(order_id, product_id, quantity, product_name)
PK = (order_id, product_id)

product_id -> product_name     <- partial dependency (only depends on PART of the key)
```

## Problem
Show that this table violates 2NF and provide the corrected decomposition.

## Solution
2NF requires: no non-key attribute depends on only *part* of a composite primary key. Here `product_name` depends only on `product_id` (part of the key), not on the whole `(order_id, product_id)` pair - a **partial dependency**, which violates 2NF.

Decomposition:
```sql
CREATE TABLE Product (
    product_id   INT PRIMARY KEY,
    product_name VARCHAR(100)
);

CREATE TABLE OrderItem (
    order_id   INT,
    product_id INT,
    quantity   INT,
    PRIMARY KEY (order_id, product_id),
    FOREIGN KEY (product_id) REFERENCES Product(product_id)
);
```

## Takeaway
2NF only matters when you have a **composite** primary key. If a non-key column depends on just a piece of that key, pull it into its own table keyed by that piece.
