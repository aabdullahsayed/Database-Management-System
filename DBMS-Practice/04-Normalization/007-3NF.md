# 3NF (Third Normal Form)

## Scenario
`employees(employee_id, department_id, department_name)` - `department_name` doesn't depend directly on `employee_id`, it depends on `department_id`, which itself depends on `employee_id`.

## Diagram
```
employee_id -> department_id -> department_name

This is a TRANSITIVE dependency:
employee_id -> department_name   (only true because employee_id -> department_id -> department_name)
```

## Problem
Show why this violates 3NF and decompose it.

## Solution
3NF forbids transitive dependencies: a non-key attribute (`department_name`) must depend directly on the key (`employee_id`), not through another non-key attribute (`department_id`). Here `department_name` depends on `department_id`, not on `employee_id` directly - that's transitive, violating 3NF.

Symptom in practice: if a department is renamed, you must update `department_name` on *every* employee row in that department, or the data becomes inconsistent.

Decomposition:
```sql
CREATE TABLE Department (
    department_id   INT PRIMARY KEY,
    department_name VARCHAR(100)
);

CREATE TABLE Employee (
    employee_id   INT PRIMARY KEY,
    department_id INT,
    FOREIGN KEY (department_id) REFERENCES Department(department_id)
);
```

## Takeaway
Rule of thumb for 3NF: "every non-key column depends on the key, the whole key, and nothing but the key." Renaming a department should be a one-row update, not an N-row update - if it isn't, you likely have a transitive dependency.
